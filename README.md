# Визуализация графа зависимостей Cargo — этап 2

Вариант №16. Практическая работа №2.
Пакеты Rust (Cargo). Запуск рассчитан на Windows.

## 1. Общее описание

CLI-приложение читает параметры командной строки,
загружает прямые зависимости пакета из API crates.io
и печатает их на экран. Сторонние библиотеки и команды
`cargo` не используются — только стандартная библиотека
Python.

На этом этапе программа выводит прямые зависимости.
Файл изображения и фильтр по подстроке сохраняются
в параметрах: фильтр понадобится на этапе 3,
рисунок — на этапе 5.

Берутся зависимости `kind=normal`, которые не помечены
как optional. Зависимости `dev` и `build` не печатаются.
Версия пакета — `max_stable_version` (если её нет,
`max_version`). Рядом с именем печатается требование
версии `req` из ответа API.

## 2. Описание функций и настроек

| Параметр | Назначение |
| --- | --- |
| `--package` | Имя анализируемого пакета |
| `--repo` | URL API или путь к тестовому файлу |
| `--test-mode` | Режим тестового репозитория |
| `--output` | Имя файла изображения `.svg` или `.png` |
| `--filter` | Подстрока фильтрации (этап 3) |

Базовый URL crates.io:

```text
https://crates.io/api/v1
```

Карточка пакета и список зависимостей:

```text
{repo}/crates/{package}
{repo}/crates/{package}/{version}/dependencies
```

Формат тестового репозитория — пакеты из заглавных
латинских букв, по одной строке:

```text
A: B C
B: D
C: D
D:
```

Модули `src/`: `config`, `cargo`, `http_fetch`,
`collector`, `stdio`, `main`.

## 3. Сборка и запуск (Windows)

Нужен Python 3.8 или новее. При установке с python.org
отметьте **Add python.exe to PATH**.

### Способ 1 — все проверки сразу

Двойной клик по `run.bat` или в `cmd.exe`:

```bat
cd /d путь\к\variant16
run.bat
```

Если `py` не находится, скрипт пробует `python`.
Другой пакет — аргументом, можно несколько:

```bat
run.bat tokio
run.bat serde libc cfg-if
```
Русский текст идёт в кодировке консоли Windows
(в `cmd` это обычно cp866). Режим UTF-8 macOS
и команда `chcp 65001` не используются: из-за них
окно cmd падает при запуске.

### Способ 2 — один запуск вручную

```bat
cd /d путь\к\variant16
set PYTHONPATH=.
py -3 -m src.main --package serde ^
  --repo "https://crates.io/api/v1" ^
  --output graph.svg
```

Тестовый репозиторий:

```bat
py -3 -m src.main --package A ^
  --repo fixtures\repo_simple.txt ^
  --output out.svg --test-mode
```

Юнит-тесты:

```bat
cd /d путь\к\variant16
set PYTHONPATH=.
py -3 -m unittest discover -s tests -v
```

### Запуск из PyCharm

1. Открыть папку `variant16` как проект.
2. Interpreter: установленный Python 3.
3. ПКМ по `demo.py` → **Run**.
4. Либо ПКМ по `src/main.py` → **Run** и Parameters:

```text
--package serde --repo https://crates.io/api/v1 --output graph.svg
```

Environment: `PYTHONPATH=.`  
Working directory: папка `variant16`.

## 4. Примеры использования

Прямые зависимости `serde` (актуальная stable-версия
на crates.io; номер требования может отличаться):

```text
=== Прямые зависимости: serde ===
serde_core =1.0.229
==========================
```

Тестовый репозиторий, пакет `A`:

```text
=== Прямые зависимости: A ===
B
C
==========================
```

Пакет без прямых normal-зависимостей, например лист `D`
в тестовом файле:

```text
=== Прямые зависимости ===
(нет)
==========================
```

Ошибка без `--package`:

```text
Ошибка: не задан параметр --package
```

Сравнение с `cargo tree`. Штатная команда смотрит
конкретный проект: features, `Cargo.lock` и платформу.
У `serde` зависимость `serde_derive` optional и
включается feature `derive` (он входит в default),
поэтому `cargo tree` часто показывает `serde_derive`.
Эта программа берёт только обязательные normal-зависимости
самой библиотеки, и для `serde` это `serde_core`.
Платформенные зависимости с полем `target` в список входят:
без сборки под конкретную ОС их нельзя отсечь так,
как это делает cargo.
